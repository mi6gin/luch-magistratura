# Демонстрация проекта на защите

## Что подтверждает проект

Тема: исследование и разработка нейросетей для прогнозирования потребности
в товарных запасах. Сопоставление с ИУП: [IUP_ACCEPTANCE.md](IUP_ACCEPTANCE.md).
Теория и методика: [RESEARCH_METHODOLOGY.md](RESEARCH_METHODOLOGY.md).
Основные результаты: [исследовательский отчёт](research/full-study/report.md).

1. Показать постановку задачи: история продаж → прогноз → решение о запасах.
   Объяснить различие продаж, скрытого спроса и закупочной рекомендации.
2. Открыть `ml/research/models.py`: реальные реализации LSTM, GRU, Transformer,
   единые входные признаки, функция потерь и квантильный выход.
3. Открыть протокол, правила очистки и train/validation/test. Параметры выбирались
   до итогового test. Показать все seeds, а не лучший запуск.
4. Показать таблицы точности, времени, параметров, сегментов, сценариев и RAM.
   Объяснить результат baseline и ограниченность выводов одним магазином.
5. Выполнить inference трёх сохранённых нейросетей на публичном UCI-примере.
6. Запустить веб-приложение: склад, симулятор, закупки, отчёты, реестр моделей.
   Объяснить, какая опубликованная политика применяется к конкретному складу.
   Исследовательские веса UCI не выдавать за обучение на данных предприятия.

## Команды

Из корня репозитория после установки `requirements-ml.txt`:

```powershell
.venv-ml\Scripts\python.exe -m ml.research.demo --checkpoint docs/research/full-study/demo/lstm.pt --example docs/research/full-study/demo/example.json
.venv-ml\Scripts\python.exe -m ml.research.demo --checkpoint docs/research/full-study/demo/gru.pt --example docs/research/full-study/demo/example.json
.venv-ml\Scripts\python.exe -m ml.research.demo --checkpoint docs/research/full-study/demo/transformer.pt --example docs/research/full-study/demo/example.json
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1 -Mode web -Port 8765
```

Прогноз воспроизводится без скачивания исходных транзакций: в репозитории
сохранены веса, порядок признаков, масштаб train и пример истории.
Полное обучение требует скачивания официального UCI-файла; команды находятся
в основном отчёте. Зависимости, окружения, `.env` и данные покупателей в Git не входят.

## Вопросы, к которым нужно подготовиться

- **Почему baseline мог победить?** Это допустимый измеренный результат.
  Сложность модели сама по себе не обеспечивает точность. Вывод ограничен
  исследованной выборкой, сеткой параметров и бюджетом обучения.
- **Что означает WAPE?** Относительная суммарная абсолютная ошибка. Это не
  процент правильных ответов. 100 − WAPE не следует называть точностью модели.
- **Почему интервалы покрывают меньше 80%?** Порядок квантилей не обеспечивает
  их калибровку. Положительная нижняя граница плохо представляет массу в нуле.
  Такие интервалы требуют доработки и новой независимой проверки перед применением
  как уровня сервиса. Итоговый test не использовался для повторного подбора.
- **Предсказывается ли новая акция?** Прототипы используют исторические факторы.
  Сценарии проверяют повторяющиеся закономерности; причинный эффект новой акции
  и будущие экзогенные переменные здесь не оцениваются.
- **Как учитывается отсутствие товара?** Явные stockout-дни цензурируют целевые
  окна. UCI не содержит доступности товара, поэтому оцениваются наблюдаемые продажи.
- **Что доказывают синтетические сценарии?** Поведение на управляемом генераторе.
  Они дополняют проверку на реальных данных и не заменяют внешнюю валидацию.
- **Как измерялась масштабируемость?** Свежий процесс, одинаковое число потоков,
  заранее заданные размеры и бюджет, два повторения. RAM включает весь процесс.
- **Готово ли промышленное внедрение?** Проект содержит исследовательские
  прототипы и рабочее приложение. Внешние склады, GPU и промышленная нагрузка
  не проверялись; применимость требует validation на данных конкретного склада.

Научные и административные требования различаются: этот репозиторий предоставляет
код и исследовательские материалы, но не подтверждает практику, подписи, доклад
на конференции или решение комиссии.
